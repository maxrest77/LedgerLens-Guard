## Hardening Sprint (Priorities 1 – 8, 2026-09-04)

| Rank | Hardening Item | Ground Truth & Vulnerability | Remediation Applied | Verification & Impact |
| :--- | :--- | :--- | :--- | :--- |
| **#1** | **Centralized Secrets & Config Validation** | Secret keys (`SECRET_KEY`, webhook HMAC secrets) were scattered across route modules or fell back to default static strings without startup validation. | Built `backend/config/settings.py` with `Settings` class and `validate_settings()`. Enforces strict production fail-fast if `SECRET_KEY` is empty, default, or $<32$ characters. Injected dynamic `_DynamicSecret` proxy in `webhook_verify.py` to support runtime test overrides without breaking static imports. Created `.env.example`. | Production startup aborts on insecure secrets; dev mode logs warnings. All 161 backend tests pass without signature drift. |
| **#2** | **React Error Boundaries** | Unhandled runtime errors in any React component tree or route could cause a catastrophic white screen of death for reviewers and admins during live usage. | Authored `ErrorBoundary.tsx` featuring both a class-based `<ErrorBoundary>` with stack-trace inspection, retry buttons, and dark-theme fallback, and a `<RouteErrorBoundary>` for React Router error elements. Wrapped root in `main.tsx` and all layout route elements in `router.tsx`. | Graceful localized recovery UI on component render crashes; zero unhandled page blowouts. |
| **#3** | **API Pagination & SQL Query Aggregation** | The `/api/reconciliation/workspace` endpoint was loading all database records into memory (`all_scoped = session.exec(base_scoped).all()`) to calculate summary KPIs, creating an $O(N)$ memory and CPU bottleneck under high volume. `/api/audit/blocks` had unbounded output. | Replaced in-memory Python iteration in `backend/api/routes/reconciliation.py` with SQL aggregate queries (`select(ReconciliationCase.status, func.count(...), func.coalesce(func.sum(...))).group_by(...)`). Added backward-compatible `page` and `limit` query parameters with pagination metadata (`total`, `page`, `limit`, `pages`) to `/api/audit/blocks`. | Database engine handles grouping and aggregation directly; audit blocks now support scalable cursor/page pagination while maintaining full backward-compatibility for legacy frontends. |
| **#4** | **`datetime.utcnow()` Deprecation Cleanup** | Over 790 deprecation warnings were emitted across Python 3.12+ test runs due to standard library deprecation of `datetime.utcnow()` across schemas, routes, and engines, risking future runtime breakage. | Created `backend/utils/time_utils.py` exporting `utc_now() -> datetime` (timezone-naive UTC compatible with SQLite string sorting and ISO standards). Systematically refactored `backend/data/schema.py` `default_factory`, 19 backend route/engine files, and 12 test suites. | Deprecation warnings reduced from 790+ down to framework-internal warnings only. All 161 backend tests pass seamlessly. |
| **#5** | **Frontend Code Splitting & Lazy Routes** | Monolithic frontend build bundled all 17 pages and heavy vendor libraries (Lucide icons, Recharts) into a single synchronous 1.36 MB index bundle, leading to slow initial load and high TTFB. | Created dark-theme animated `PageLoader.tsx`. Converted all 17 page imports in `router.tsx` to dynamic `React.lazy()` imports wrapped in `Suspense`. Configured manual vendor chunking in `vite.config.ts` separating React, Recharts, Lucide, and core vendors. | Initial index JS bundle plummeted from **1.36 MB down to 47.17 kB** (14.5 kB gzipped). Largest vendor chunk is under 476 kB. Production build finishes in 2.33s with 0 errors. |
| **#6** | **Continuous Integration Pipeline (GitHub Actions)** | Lack of automated CI meant regressions could be introduced into master/main undetected without manual pytest and build executions. | Engineered `.github/workflows/ci.yml` with dual parallel jobs: `backend-test` (Python 3.12 with `astral-sh/setup-uv@v5` running `pytest -v`) and `frontend-build` (Node 20 with `pnpm/action-setup@v3` running `tsc -b && vite build`) triggered on push/PR to `master` and `main`. | Automated validation on every commit; fast isolated execution via locked dependencies and action caching. |
| **#7** | **PostgreSQL Migration Dry-Run & Verification** | Migration script `migrate_sqlite_to_postgres.py` was unverified against PostgreSQL dialect compilation and lacked automated validation of table topological dependency ordering and WORM hash preservation. | Enhanced script with `--dry-run` CLI flag, PostgreSQL DDL dialect compiler, table row audit, and isolated engine support.
